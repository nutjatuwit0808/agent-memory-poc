# Case 8214 — Membership คำนวณด้วย Event Data เก่าจาก Ingester Backlog

## สรุปเคส

ทีม marketing สังเกตว่า segment สำหรับ high-value customer มีขนาดเล็กกว่าที่คาดมากหลังจาก campaign ใหม่เปิดตัว ทั้งที่มี purchase activity สูงช่วงวันก่อนหน้า

## การตรวจสอบ

ตรวจ [[structure/synthetic-customer-segmentation/module-membership-refresher]] พบว่า refresh รอบล่าสุดใช้ event data จาก [[structure/synthetic-customer-segmentation/module-event-ingester]] ที่ค้างอยู่ใน backlog กว่า 6 ชั่วโมง ทำให้ purchase event ช่วงค่ำไม่ถูกนำมาคำนวณ

## สาเหตุ

ช่วง peak traffic ของ e-commerce ทำให้ ingestion rate เกิน throughput ของ event-ingester ทำให้ backlog สะสม — refresh ตาม schedule ปกติไม่รอให้ backlog clear ก่อน ทำให้ได้ snapshot ที่ไม่สมบูรณ์

## การแก้ไข

รัน manual refresh หลังจาก backlog clear แล้ว ได้ membership ที่ถูกต้องและ export ไปยัง channel สำเร็จ ผลของ campaign ล่าช้าไป 8 ชั่วโมงจากแผน

## Follow-up

เพิ่ม pre-refresh check ว่า event ingestion lag ต่ำกว่าเกณฑ์ก่อน trigger refresh และ scale ingester service เพิ่มในช่วง peak ตาม [[deployment/synthetic-customer-segmentation/scaling-policy]]
