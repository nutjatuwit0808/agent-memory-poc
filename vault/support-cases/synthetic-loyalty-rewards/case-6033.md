# Case 6033 — Expiry batch job รันสองครั้งในคืนเดียว

## สรุปเคส

สมาชิกหลายร้อยคนแจ้งว่าแต้มหายมากกว่าที่ควรเป็น ตรวจสอบพบว่า expiry job รันสองรอบในคืนนั้น expire แต้มซ้ำ

## การตรวจสอบ

ตรวจ cron log ของ [[structure/synthetic-loyalty-rewards/module-expiry-scheduler]] พบว่า instance ใหม่เริ่มรันทั้งที่ instance เดิมยังไม่เสร็จ เพราะ batch ใช้เวลานานกว่า schedule interval

## สาเหตุ

ไม่มี distributed lock ป้องกัน expiry job รันซ้อนกัน ปัญหาไม่เคยเจอก่อนหน้าเพราะ vault ขนาดเล็กกว่า แต่หลังสมาชิกเพิ่มขึ้น 3 เท่าใน 6 เดือน batch ใช้เวลานานขึ้นเกิน schedule

## การแก้ไข

หยุด instance ที่กำลังรันอยู่ทั้งหมด audit affected accounts ทั้งหมด คืนแต้มที่หักเกินไป และเพิ่ม advisory lock ก่อน job เริ่มรัน

## Follow-up

เพิ่ม advisory lock และ idempotency check โดยใช้ `batchDate` เป็น key ป้องกัน process วันเดิมซ้ำ ดู [[deployment/synthetic-loyalty-rewards/expiry-job-scheduling-runbook]]
