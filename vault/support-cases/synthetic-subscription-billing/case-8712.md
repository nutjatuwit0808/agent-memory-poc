# Case 8712 — Downgrade มีผลทันทีแทนที่จะรอสิ้นสุดรอบบิล

## สรุปเคส

ลูกค้าหลายรายที่ขอ downgrade แพลนพบว่าฟีเจอร์ของแพลนเดิมถูกปิดใช้งานทันที ทั้งที่ตาม [[business-logic/synthetic-subscription-billing/downgrade-effective-date-policy]] ควรมีผลเมื่อสิ้นสุดรอบบิลเท่านั้น

## การตรวจสอบ

ตรวจ `changePlan` ใน [[structure/synthetic-subscription-billing/module-plan-manager]] พบว่า deploy ใหม่ที่เพิ่ม feature 'เปลี่ยนแพลนด่วน' (สำหรับกรณี compliance) มี default parameter ผิดพลาดที่ทำให้ทุกการ downgrade ถูกประมวลผลแบบทันทีโดยไม่ตั้งใจ แทนที่จะเป็น default แบบรอสิ้นสุดรอบบิล

## สาเหตุ

การเพิ่ม feature ใหม่เปลี่ยน default behavior ของฟังก์ชันเดิมโดยไม่ได้ตรวจสอบ regression กับ flow ปกติที่ใช้งานอยู่แล้ว

## การแก้ไข

คืนสิทธิ์การใช้ฟีเจอร์แพลนเดิมให้ลูกค้าที่ได้รับผลกระทบจนกว่าจะสิ้นสุดรอบบิลจริงตามนโยบาย แก้ default parameter ให้ถูกต้อง

## Follow-up

เพิ่ม regression test ครอบคลุม flow downgrade ปกติก่อน merge feature ใหม่ใดๆ ที่แตะฟังก์ชัน `changePlan` เพื่อป้องกัน default behavior เปลี่ยนโดยไม่ตั้งใจอีก
