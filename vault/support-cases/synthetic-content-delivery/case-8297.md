# Case 8297 — Cache Key Collision ระหว่าง Tenant สองรายที่ใช้ Origin URL เดียวกัน

## สรุปเคส

Tenant B ได้รับเนื้อหาของ Tenant A จาก cache แทนที่จะเป็นเนื้อหาของตัวเอง เกิดขึ้นเฉพาะกับ content บาง URL ที่ทั้งสอง tenant ใช้ origin domain เดียวกัน

## การตรวจสอบ

ตรวจ cache key generation ใน [[structure/synthetic-content-delivery/module-cache-coordinator]] พบว่า cache key ถูกสร้างจาก URL เพียงอย่างเดียวโดยไม่มี tenant namespace — ทำให้ tenant ที่ใช้ reseller origin URL เดียวกันมี cache key ชนกัน

## สาเหตุ

Code path สำหรับ tenant ที่ใช้ shared origin (reseller plan) ไม่ได้ prepend `tenant_id` ใน cache key เพราะคาดว่า origin URL ต่างกันอยู่แล้ว แต่ใน reseller case มี URL เดียวกันจริงๆ

## การแก้ไข

Patch ให้ cache key รวม `tenant_id` เสมอโดยไม่มีข้อยกเว้น flush cache ที่อาจมี collision ทั้งหมดสำหรับ tenant ในแผน reseller

## Follow-up

เพิ่ม property test สำหรับ cache key uniqueness ที่ verify ว่า tenant pair ใดๆ ไม่มีทาง generate cache key ชนกันได้ และอัปเดต [[business-logic/synthetic-content-delivery/tenant-isolation-policy]] ด้วยตัวอย่างกรณีนี้
