# Case 4830 — Depreciation Schedule คำนวณด้วยวันเริ่มต้นผิดทำให้ Book Value ผิดปีงบประมาณ

## สรุปเคส

ทีม finance พบระหว่างปิดบัญชีไตรมาสว่า server กลุ่มหนึ่ง (10 เครื่อง) มี book value สูงกว่าที่ควรจะเป็นเกือบ 20% เนื่องจาก depreciation เดินผิดจังหวะ

## การตรวจสอบ

ตรวจ schedule ใน [[structure/synthetic-asset-management/module-depreciation-engine]] พบว่า `startDate` ของ server กลุ่มนี้ถูก set เป็นวันที่ออก PO แทนที่จะเป็นวันที่รับสินค้าจริง ซึ่งต่างกันเกือบ 3 เดือน

## สาเหตุ

ตอน `markAsReceived` ถูกเรียกโดย [[structure/synthetic-asset-management/module-procurement-handler]] มีการส่ง `purchaseDate` แทน `receivedDate` เป็น startDate ไปยัง [[structure/synthetic-asset-management/module-depreciation-engine]] เป็น bug ใน integration code ระหว่างสอง module

## การแก้ไข

เรียก `recomputeSchedule` สำหรับ server ทั้ง 10 เครื่องด้วย `correctedStartDate` ที่ถูกต้อง ทีม finance ทำ audit adjustment สำหรับไตรมาสที่บันทึกผิดไปแล้ว

## Follow-up

แก้ integration code ใน [[structure/synthetic-asset-management/module-procurement-handler]] ให้ส่ง `receivedDate` แทน `purchaseDate` เสมอ และเพิ่ม test ที่ verify field นี้โดยเฉพาะ
