# Case 9803 — WebSocket channel ของ alert-dispatcher ค้างข้อความสะสมช่วง rush window

## สรุปเคส

ลูกค้าหลายรายรายงานว่าได้รับแจ้งเตือนล่าช้ากว่าเหตุการณ์จริง 5-10 นาทีในช่วง rush window เย็น ทั้งที่ปกติควรเป็นเรียลไทม์

## การตรวจสอบ

ตรวจ [[structure/synthetic-iot-fleet-tracker/module-alert-dispatcher]] พบว่า WebSocket connection pool มีจำนวนไม่พอรองรับ event ที่พุ่งสูงพร้อมกันจากหลายพันอุปกรณ์ ทำให้ข้อความค้างอยู่ใน internal queue ก่อนถูกส่งจริง

## สาเหตุ

การประมาณ capacity ของ WebSocket pool ตอนออกแบบครั้งแรกอิงจากปริมาณ event ตอนนั้นซึ่งน้อยกว่าปัจจุบันมาก เพราะจำนวนลูกค้าและอุปกรณ์เติบโตเร็วกว่าที่ประเมินไว้

## การแก้ไข

ขยาย WebSocket connection pool ชั่วคราวด้วยมือระหว่างรอ scale แบบถาวร แล้วติดตาม queue depth ใกล้ชิดจนกว่าจะผ่านช่วง rush window

## Follow-up

ทบทวน [[deployment/synthetic-iot-fleet-tracker/scaling-policy]] ของ alert-dispatcher-service ให้ scale ตาม event throughput จริงแทนค่า fixed capacity เดิม
