# Case 6498 — Bot Traffic หลุดผ่านช่วงที่ Rollback Fraud Rule

## สรุปเคส

หลัง rollback fraud rule ตัวหนึ่งเพราะเจอ false positive กับ publisher รายใหญ่ (ดู [[support-cases/synthetic-ad-bidding/case-3031]]) ทีมสังเกตว่ามี traffic ผิดปกติจาก bot เพิ่มขึ้นชัดเจนในสองวันถัดมา

## การตรวจสอบ

ตรวจสอบพบว่า rule ที่ rollback ไปนั้นเป็นตัวหลักที่จับ bot pattern ประเภทหนึ่งได้ดี การ rollback ทั้ง rule แทนที่จะปิดเฉพาะส่วนที่ทำให้เกิด false positive กับ publisher รายนั้น เปิดช่องให้ bot pattern เดิมกลับมาผ่านได้อีกครั้ง

## สาเหตุ

ตอน rollback ทีมรีบแก้ปัญหา false positive จนเลือก rollback ทั้ง rule แทนที่จะแก้เฉพาะ condition ที่เกี่ยวกับ publisher รายนั้น เพราะเวลากดดันและ rule มีความซับซ้อนสูงเกินจะแยกแก้ทันที

## การแก้ไข

เขียน rule ใหม่ที่แยก condition สำหรับ publisher ที่อยู่ใน allowlist ออกจาก logic การจับ bot pattern หลัก แล้ว deploy กลับพร้อม allowlist ตาม [[business-logic/synthetic-ad-bidding/fraud-score-threshold-policy]]

## Follow-up

ปรับ [[deployment/synthetic-ad-bidding/rollback-procedure]] ให้มีขั้นตอนเฉพาะสำหรับ fraud rule โดยเน้นย้ำให้แยกแก้เฉพาะจุดแทนการ rollback ทั้ง rule เมื่อเป็นไปได้
