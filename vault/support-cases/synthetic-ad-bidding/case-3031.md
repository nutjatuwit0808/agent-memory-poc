# Case 3031 — Fraud Filter บล็อก Traffic จริงจาก Publisher รายใหญ่เกือบทั้งหมด

## สรุปเคส

publisher รายหนึ่งซึ่งปกติมี fill rate สูงแจ้งว่า bid request ของตัวเองถูก AdPulse ปฏิเสธเกือบ 95% อย่างกะทันหันตั้งแต่เช้าวันหนึ่ง

## การตรวจสอบ

ตรวจ [[structure/synthetic-ad-bidding/module-fraud-filter]] พบว่า rule ใหม่ที่เพิ่งเปิดใช้เมื่อคืน (ตรวจจับ pattern การส่ง request ถี่ผิดปกติจาก IP เดียว) ให้คะแนน fraud สูงเกิน `FRAUD_SCORE_BLOCK_THRESHOLD` กับ traffic เกือบทั้งหมดของ publisher รายนี้

## สาเหตุ

publisher รายนี้ใช้สถาปัตยกรรม server-side rendering ที่รวม request จากผู้ใช้จริงหลายพันคนผ่าน proxy ตัวเดียวกันก่อนส่งเข้า AdPulse ทำให้ pattern ดูเหมือน request ถี่จาก IP เดียวทั้งที่เป็นผู้ใช้จริงคนละคน rule ใหม่ไม่ได้ทดสอบกับ traffic pattern แบบนี้มาก่อน

## การแก้ไข

ปิด rule ใหม่ชั่วคราวสำหรับ publisher รายนี้โดยเฉพาะผ่าน allowlist ตาม [[business-logic/synthetic-ad-bidding/fraud-score-threshold-policy]] แล้วปรับ rule ให้แยกแยะ pattern proxy ที่ถูกต้องออกจาก bot จริงก่อนเปิดใช้กว้างอีกครั้ง

## Follow-up

เพิ่มขั้นตอนทดสอบ rule ใหม่กับ traffic sample ของ publisher รายใหญ่ทุกรายก่อน rollout เต็มรูปแบบ เพิ่มเข้า [[convention/synthetic-ad-bidding/code-review-checklist]]
