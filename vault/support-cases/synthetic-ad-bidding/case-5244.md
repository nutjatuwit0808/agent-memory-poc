# Case 5244 — หักเงินแคมเปญซ้ำจาก Win Notice ที่ noticeId ชนกันข้าม SSP

## สรุปเคส

ทีมการเงินพบว่าแคมเปญกลุ่มหนึ่งถูกหักเงินสูงกว่าจำนวนครั้งที่ชนะประมูลจริงตามรายงานของ SSP

## การตรวจสอบ

ตรวจ [[structure/synthetic-ad-bidding/module-win-notice-processor]] พบว่า dedup logic ใช้ `noticeId` เดี่ยวๆ เป็น key โดยไม่รวม SSP ที่ส่งมา และพบว่า noticeId ชนกันระหว่าง SSP สองรายที่ generate ID ด้วย pattern คล้ายกัน

## สาเหตุ

SSP ทั้งสองรายไม่ได้รับประกัน uniqueness ของ noticeId ในระดับ global ตาม spec — ทีมออกแบบ dedup ตอนแรกสมมติว่า noticeId unique เสมอโดยไม่ได้ตรวจสอบสมมติฐานนี้กับ SSP ทุกราย

## การแก้ไข

แก้ dedup key เป็น `(sspId, noticeId)` คู่กันทันที แล้วตรวจสอบ win notice ย้อนหลัง 7 วันเพื่อหาแคมเปญที่ถูกหักเงินซ้ำจริง คืนเงินส่วนต่างให้ครบทุกรายที่ได้รับผลกระทบ

## Follow-up

เพิ่มเข้า [[business-logic/synthetic-ad-bidding/win-notice-dedup-policy]] เป็นข้อยกเว้นถาวร และตรวจสอบ SSP ใหม่ทุกรายที่จะต่อระบบว่ามี noticeId ชนกับ SSP เดิมหรือไม่ก่อนเปิดใช้งานจริง
