# Case 3765 — Notary Provider ล่มพร้อมกันบล็อกการปิดดีลชุดใหญ่

## สรุปเคส

ลูกค้ารายใหญ่รายหนึ่งมี envelope ประมาณ 40 ฉบับที่ signer เซ็นครบแล้วแต่ค้างสถานะ `pending_notarization` พร้อมกัน เพราะ notary provider หลักที่ใช้ล่มทั้งระบบนานเกือบ 6 ชั่วโมง

## การตรวจสอบ

ตรวจ [[structure/synthetic-document-signing/module-notary-integration]] พบว่า `requestNotarySession` ทุกคำขอไปยัง provider นี้ตั้งแต่ช่วงเวลาดังกล่าว timeout หมด และ `retryNotarySession` ก็ล้มเหลวซ้ำเช่นกันเพราะ provider ล่มจริง ไม่ใช่ปัญหาชั่วคราวรายคำขอ

## สาเหตุ

ระบบใช้ notary provider เดียวเป็น hard dependency ไม่มี fallback provider สำรอง ทำให้เมื่อ provider หลักล่ม envelope ทั้งหมดที่ต้องผ่าน notary ค้างพร้อมกันโดยไม่มีทางเลือกอื่นเลย

## การแก้ไข

รอ provider กลับมาให้บริการปกติแล้วรัน `retryNotarySession` เป็นชุดให้ทุก envelope ที่ค้าง พร้อมแจ้งลูกค้าที่ได้รับผลกระทบเป็นรายบุคคลเรื่องความล่าช้า

## Follow-up

เสนอเพิ่ม notary provider สำรองอย่างน้อยหนึ่งรายที่สามารถสลับไปใช้ได้เมื่อ provider หลักมีปัญหานานเกินเกณฑ์ที่กำหนด พิจารณาคู่กับ [[business-logic/synthetic-document-signing/notary-requirement-policy]] เรื่องการเลือก provider สำรองให้ลูกค้า
