# Case 8986 — พบ Hash Mismatch ใน Audit Trail ระหว่างการตรวจสอบ Compliance

## สรุปเคส

ระหว่างการตรวจสอบ compliance ประจำปีของลูกค้ารายใหญ่ พบว่า envelope บางฉบับที่สร้างเมื่อ 8 เดือนก่อนมี hash chain ที่ verify ไม่ผ่านเมื่อรัน `verifyChainIntegrity`

## การตรวจสอบ

ตรวจสอบ `audit_events` ของ envelope ที่มีปัญหาพบว่ามี event หนึ่งหายไปจาก chain ตรง timestamp ที่ตรงกับช่วงที่ทีม infrastructure ทำ database migration ครั้งใหญ่เมื่อ 8 เดือนก่อน

## สาเหตุ

migration script ตัวหนึ่งที่ควรแค่ copy ข้อมูลไปตาราง partition ใหม่ มี bug ที่ข้าม row บางแถวที่มี timestamp คาบเกี่ยวกับช่วงเวลาที่ migration กำลังรัน (race condition ระหว่าง insert สดกับ migration read) ทำให้ event บางตัวไม่ถูก copy ไปตารางใหม่

## การแก้ไข

กู้ event ที่หายจาก database backup ก่อน migration แล้วสร้าง event `chain_gap_documented` ตามที่ [[business-logic/synthetic-document-signing/audit-trail-integrity-policy]] กำหนด พร้อมแนบหลักฐาน backup ประกอบ แจ้งทีมกฎหมายของลูกค้าให้ทราบก่อนใช้เอกสารกลุ่มนี้ต่อ

## Follow-up

ห้าม migration script ใดๆ แตะตาราง `audit_events` ระหว่างมีการเขียนสด (live traffic) อีก ต้องหยุดรับ write ชั่วคราวหรือใช้วิธี migrate แบบ dual-write แทนเสมอ เพิ่มเป็นข้อบังคับใน [[deployment/synthetic-document-signing/template-schema-migration-runbook]]
