# Case 3401 — คืนเงินหลายรายการค้างพร้อมกันช่วงบ่าย

## สรุปเคส

ทีม support ได้รับแจ้งจากลูกค้าหลายรายพร้อมกันในช่วงบ่ายวันเดียวกัน ทุกรายบอกว่าคำขอคืนเงินค้างสถานะ "กำลังดำเนินการ" นานผิดปกติ

## การตรวจสอบ

เช็ค dashboard ภายในพบว่าจำนวนคำขอคืนเงินที่เป็น `stuck` พุ่งขึ้นพร้อมกันในเวลาไล่เลี่ยกัน ไม่ใช่เคสเดี่ยวแบบปกติ — ทีม engineering ยกระดับเป็น incident ทันที รายละเอียดการรับมือเต็มรูปแบบบันทึกไว้ที่ [[deployment/incident-response-runbook]] หัวข้อ "กรณี refund ค้างจำนวนมากพร้อมกัน"

## สาเหตุ

payment gateway (คนละตัวกับที่เคยมีปัญหาใน case-2891) ตอบ webhook ยืนยันการคืนเงินช้ากว่าปกติมากทั้งระบบ ไม่ใช่ปัญหาเฉพาะ transaction เดียว

## การแก้ไข

ทีมปรับ `REFUND_STUCK_THRESHOLD_MIN` ชั่วคราวเพื่อลด false positive ระหว่างที่ gateway กำลังฟื้นตัว ตามที่อธิบายไว้ใน [[business-logic/refund-timeout-policy]] แล้วแจ้งลูกค้าทุกรายที่ได้รับผลกระทบว่ากำลังดำเนินการอยู่

## Follow-up

ปิด incident หลังสถานการณ์กลับสู่ปกติ เขียน postmortem ตามกติกา blameless
