# Case 2891 — ลูกค้าขอคืนเงินแล้วระบบค้าง

## สรุปเคส

ลูกค้าแจ้งว่าขอคืนเงินสำหรับ order #ORD-88214 ตั้งแต่เมื่อวาน แอปแสดง "กำลังดำเนินการ" มาตลอด ยังไม่ได้รับเงินคืนและไม่มีความคืบหน้าใดๆ ลูกค้าเริ่มไม่พอใจเพราะรอมาเกิน 24 ชั่วโมงแล้ว

## การตรวจสอบ

เช็คสถานะ refund ในระบบภายในพบว่าอยู่ในสถานะ `stuck` มาตั้งแต่เมื่อวาน — ตรงกับนิยามใน [[business-logic/refund-timeout-policy]] ที่ค้างเกิน `REFUND_STUCK_THRESHOLD_MIN` แล้วไม่มีการ retry อัตโนมัติ

## สาเหตุ

payment gateway ไม่ส่ง webhook ยืนยันการคืนเงินกลับมา ตรวจสอบฝั่ง gateway dashboard พบว่า transaction คืนเงินจริงสำเร็จแล้วที่ฝั่ง gateway แต่ webhook หายไประหว่างทาง (ปัญหาเดียวกับที่อธิบายไว้ใน [[structure/module-refund]] เรื่อง state `stuck`)

## การแก้ไข

วิศวกร on-call เรียก `verifyPayment` ยืนยันสถานะจริงจาก gateway โดยตรง แล้ว trigger การอัปเดตสถานะด้วยมือให้เป็น `completed` เงินเข้าบัญชีลูกค้าจริงภายใน 10 นาทีหลังจากนั้น

## Follow-up

แจ้งลูกค้าเรียบร้อย ปิดเคส — เพิ่มเข้า pattern ที่ทีมกำลังพิจารณาว่าควรมี job อัตโนมัติ query สถานะจาก gateway เมื่อ refund อยู่ใน `stuck` เกิน 1 ชั่วโมง แทนที่จะรอให้วิศวกรทำด้วยมือทุกครั้ง
