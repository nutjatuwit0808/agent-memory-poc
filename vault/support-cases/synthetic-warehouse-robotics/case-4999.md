# Case 4999 — ตั้งค่า throttling ผิดทำให้พลาด shipping cutoff

## สรุปเคส

วันหนึ่งพบว่า order จำนวนมากไม่ถูกหยิบทันเวลา shipping cutoff ทั้งที่คิวไม่ได้ยาวผิดปกติมากนัก

## การตรวจสอบ

ตรวจ config ของ [[business-logic/synthetic-warehouse-robotics/peak-hour-throttling-policy]] พบว่าค่า `TASK_QUEUE_MAX_DEPTH` ถูกปรับลดลงระหว่างการทดสอบ config ใหม่เมื่อสัปดาห์ก่อน แต่ไม่ได้ปรับกลับหลังทดสอบเสร็จ

## สาเหตุ

ค่าที่ต่ำเกินไปทำให้ระบบเริ่ม throttle order ใหม่จาก WMS เร็วกว่าที่ควรมาก ทั้งที่หุ่นยนต์ยังมีกำลังการหยิบเหลืออยู่มาก

## การแก้ไข

ปรับค่า `TASK_QUEUE_MAX_DEPTH` กลับเป็นค่าที่ตั้งใจไว้เดิมทันที แล้วเร่งประมวลผล order ที่ตกค้างเป็นพิเศษเพื่อให้ทันรอบ shipping ถัดไป

## Follow-up

เพิ่มขั้นตอนยืนยันคืนค่า config หลังการทดสอบทุกครั้งเป็นส่วนหนึ่งของ [[convention/synthetic-warehouse-robotics/code-review-checklist]] สำหรับการเปลี่ยน config ที่กระทบ throttling
