# Case 2532 — picking-engine ตอบสนองช้าลงหลัง promo ทำ order พุ่ง

## สรุปเคส

ช่วง promo ใหญ่ order พุ่งขึ้น 3 เท่าจากปกติ ทีมสังเกตว่าเวลาเฉลี่ยตั้งแต่มอบหมายงานถึงเริ่มหยิบจริงช้าลงจาก 8 วินาทีเป็นเกือบ 40 วินาที

## การตรวจสอบ

ตรวจ metric ของ [[structure/synthetic-warehouse-robotics/module-picking-engine]] พบว่า `computeGripProfile` ถูกเรียกซ้ำสำหรับ SKU เดิมทุกครั้งแทนที่จะ cache ผลลัพธ์ไว้ ทำให้ CPU ของ service พุ่งสูงตอน load เยอะ

## สาเหตุ

ตอนออกแบบ engine ครั้งแรก คาดว่าจำนวน SKU ที่ active พร้อมกันจะน้อย จึงไม่เห็นความจำเป็นต้อง cache — แต่ promo ทำให้ SKU ยอดนิยมถูกหยิบซ้ำจำนวนมากในเวลาสั้นๆ

## การแก้ไข

เพิ่ม in-memory cache สำหรับ grip profile แบบเร่งด่วน (TTL 1 ชั่วโมง) deploy เป็น hotfix ระหว่าง promo ทำให้ latency กลับมาใกล้เคียงปกติภายใน 15 นาทีหลัง deploy

## Follow-up

นำ caching layer เข้า scope งานถัดไปอย่างเป็นทางการแทนการเป็น hotfix พร้อมทบทวน [[deployment/synthetic-warehouse-robotics/scaling-policy]] ของ service นี้สำหรับ promo ในอนาคต
