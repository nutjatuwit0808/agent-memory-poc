# Case 6247 — คิว task ค้างสะสมหลัง network outage สั้นๆ

## สรุปเคส

หลัง network ภายในคลังหลุดไปประมาณ 4 นาที คิว [[structure/synthetic-warehouse-robotics/module-task-scheduler]] มี task ค้างสะสมกว่า 300 รายการทันทีที่ network กลับมา

## การตรวจสอบ

พบว่า order จาก WMS ยังคงส่งเข้ามาต่อเนื่องระหว่าง outage และถูก buffer ไว้ที่ API gateway แต่ scheduler ประมวลผลทีละ task ตามปกติทำให้ไล่ backlog ไม่ทัน

## สาเหตุ

ไม่มี logic พิเศษสำหรับสถานการณ์ backlog ขนาดใหญ่ที่เกิดจาก outage — scheduler ปฏิบัติกับ burst แบบนี้เหมือน load ปกติ ทำให้ throttling ตาม [[business-logic/synthetic-warehouse-robotics/peak-hour-throttling-policy]] ไม่ถูก trigger เพราะไม่ใช่ peak window ตามเวลาแต่โหลดสูงจริง

## การแก้ไข

วิศวกร on-call เปิด throttling ด้วยมือชั่วคราวนอกช่วง peak window ปกติ เพื่อกัน queue ไม่ให้ล้นขณะไล่ backlog ใช้เวลาประมาณ 40 นาทีจนคิวกลับสู่ปกติ

## Follow-up

เสนอให้ throttling ผูกกับ queue depth จริงแทนการผูกกับช่วงเวลาคงที่ อยู่ระหว่างพิจารณาว่าจะปรับ [[business-logic/synthetic-warehouse-robotics/peak-hour-throttling-policy]] หรือไม่
