# Case 8213 — กด Schedule Campaign ซ้ำสองครั้งเร็วๆ ทำให้เกิด Campaign ซ้อนสองตัว

## สรุปเคส

ทีม marketing คนหนึ่งกดปุ่ม schedule สองครั้งติดกันเพราะ UI ตอบสนองช้า พบภายหลังว่าระบบสร้าง send job สองชุดจาก campaign เดียวกัน ส่งซ้ำให้ผู้รับทุกคน

## การตรวจสอบ

ตรวจ [[structure/synthetic-marketing-automation/module-campaign-builder]] พบว่า `scheduleCampaign` ไม่มีการล็อกระดับ campaign ก่อนเปลี่ยนสถานะจาก `validated` เป็น `scheduled` — สอง request ที่มาพร้อมกันต่างอ่านเห็นสถานะ `validated` เหมือนกันแล้วต่างก็ผ่านเงื่อนไขไปสร้าง send job ของตัวเอง

## สาเหตุ

การ query และ update สถานะ campaign ไม่ได้ทำแบบ atomic — ช่วงเวลาสั้นๆ ระหว่างอ่านกับเขียนเปิดโอกาสให้ request คู่ขนานแทรกเข้ามาได้ เป็นรูปแบบบั๊กเดียวกับที่เคยพบใน service อื่นที่มี pattern อ่าน-แล้ว-เขียนคล้ายกัน

## การแก้ไข

หยุด send job ที่ซ้ำซ้อนตัวหนึ่งทันที (ตัวที่ยังไม่เริ่มส่ง) แก้ให้ `scheduleCampaign` ใช้ conditional update แบบ atomic (`update ... where status='validated'`) แทนการอ่านแล้วเขียนแยกกัน deploy เป็น hotfix

## Follow-up

ตรวจสอบฟังก์ชันอื่นใน [[structure/synthetic-marketing-automation/module-campaign-builder]] ที่มี pattern อ่าน-แล้ว-เขียนคล้ายกันว่ามีความเสี่ยง race condition เดียวกันหรือไม่ และเพิ่มเข้า [[convention/synthetic-marketing-automation/code-review-checklist]]
