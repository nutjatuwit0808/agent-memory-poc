# Case 8450 — ส่ง campaign ผิดกลุ่มเพราะ segment cache เก่าค้าง

## สรุปเคส

campaign โปรโมชันสำหรับลูกค้าเก่าที่เคยซื้อ ถูกส่งไปถึงผู้สมัครใหม่ที่ยังไม่เคยซื้ออะไรเลยกว่า 8,000 คน ทำให้เนื้อหาที่อ้างอิงประวัติการซื้อดูผิดเพี้ยนไปหมด

## การตรวจสอบ

ตรวจ [[structure/synthetic-marketing-automation/module-campaign-builder]] พบว่า `validateCampaign` ใช้ segment snapshot ที่คำนวณไว้ตั้งแต่ 3 วันก่อน ทั้งที่กติกาปกติต้อง recompute ถ้าเก่าเกิน 24 ชั่วโมงตาม [[business-logic/synthetic-marketing-automation/segment-freshness-policy]]

## สาเหตุ

ตรวจโค้ดพบว่ามีการเพิ่ม in-memory cache ชั้นหนึ่งใน `validateCampaign` เพื่อลด latency ตอน preview แต่ cache นี้ไม่เคย invalidate เลยแม้ snapshot จริงใน database จะถูก recompute ใหม่แล้ว ทำให้ validate ผ่านด้วยข้อมูลเก่าที่ค้างอยู่ใน memory

## การแก้ไข

หยุด send job ที่เหลือทันที ลบ cache ชั้นที่มีปัญหาออก แล้ว recompute segment ใหม่และส่ง campaign แก้ไขเฉพาะกลุ่มที่ยังไม่ได้รับเนื้อหาที่ถูกต้อง

## Follow-up

ลบ in-memory cache ที่ซ้อนทับกับ snapshot mechanism ของ [[structure/synthetic-marketing-automation/module-segment-engine]] ออกทั้งหมด ยึดหลักว่า freshness check ต้องอ่านจาก source เดียวเท่านั้น ไม่มี cache ซ้อน
