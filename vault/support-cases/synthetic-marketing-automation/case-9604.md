# Case 9604 — ผล A/B Test เอนเอียงผิดปกติเพราะการแบ่ง Bucket ไม่สมดุล

## สรุปเคส

ทีม marketing สังเกตว่าผล A/B test ของ subject line ใหม่ดู "ชนะ" อย่างท่วมท้นเกินจริง เมื่อตรวจสอบพบว่า bucket ทั้งสองฝั่งมีขนาดต่างกันเกือบ 3 เท่า ทั้งที่ตั้งค่าไว้ 50/50

## การตรวจสอบ

ตรวจ [[structure/synthetic-marketing-automation/module-campaign-builder]] พบว่า hash function ที่ใช้แบ่ง bucket จาก `contactId` ไม่ uniform เพียงพอสำหรับ contactId ที่มีรูปแบบ prefix ซ้ำกันจำนวนมาก (เพราะ contactId ส่วนใหญ่สร้างจาก sequential id เดิม)

## สาเหตุ

hash function ที่เลือกใช้ (modulo ตรงๆ ของตัวเลขท้าย id) ไม่กระจายค่าดีพอเมื่อ input มี pattern ซ้ำเป็นชุด ทำให้ contactId ที่ลงท้ายตัวเลขคล้ายกันไปกระจุกอยู่ bucket เดียวกันเป็นจำนวนมาก

## การแก้ไข

เปลี่ยนไปใช้ cryptographic hash (เช่น SHA-256 ของ contactId) แทน modulo ตรงๆ ก่อนแบ่ง bucket แล้วรัน A/B test ใหม่อีกรอบเพื่อยืนยันผลลัพธ์ที่น่าเชื่อถือกว่าเดิม

## Follow-up

เพิ่มการตรวจสอบขนาด bucket อัตโนมัติหลังแบ่งเสร็จทุกครั้งตาม [[business-logic/synthetic-marketing-automation/ab-test-bucket-policy]] ถ้าเบี่ยงเบนเกิน 2% ให้ flag ทันทีก่อนเริ่มส่งจริง ไม่ใช่ปล่อยให้ทีม marketing สังเกตเองหลังผลออกแล้ว
