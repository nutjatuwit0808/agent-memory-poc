# Case 4520 — ผู้รับได้อีเมลเดียวกันซ้ำ 3 ฉบับจาก scheduler retry

## สรุปเคส

ลูกค้าหลายรายร้องเรียนว่าได้รับอีเมล newsletter ฉบับเดียวกันซ้ำ 2-3 ครั้งในเวลาไม่กี่นาที

## การตรวจสอบ

ตรวจ log [[structure/synthetic-marketing-automation/module-send-scheduler]] พบว่า `dispatchNextBatch` ถูกเรียกซ้ำสำหรับ batch เดิมหลายครั้ง ตรงกับช่วงที่ worker process restart กลางทางเพราะ deploy รอบปกติ

## สาเหตุ

worker ที่ restart กลาง batch ไม่ได้ทำ idempotency check ตาม [[business-logic/synthetic-marketing-automation/duplicate-send-prevention-policy]] อย่างครบถ้วน — unique constraint ที่ควรกันซ้ำใช้ `campaignId` + `contactId` เท่านั้น ไม่รวม `batchIndex` ทำให้ batch ใหม่ที่สร้างหลัง restart ผ่านการเช็คซ้ำได้เพราะมองว่าเป็นคนละ record

## การแก้ไข

แก้ unique constraint ให้ครอบคลุมครบตามที่นโยบายกำหนด แล้วส่งอีเมลขอโทษพร้อมคำอธิบายให้ผู้รับที่ได้รับอีเมลซ้ำ

## Follow-up

เพิ่ม test case สำหรับกรณี worker restart กลาง batch ใน integration test ของ send-scheduler และ audit unique constraint อื่นในระบบว่าตรงกับ policy จริงหรือไม่
