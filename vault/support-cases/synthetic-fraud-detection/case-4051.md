# Case 4051 — ml-scorer response time เกิน SLA ช่วง traffic สูง

## สรุปเคส

ช่วง peak traffic คำตอบจาก [[structure/synthetic-fraud-detection/module-ml-scorer]] ช้าเกิน `ML_SCORING_TIMEOUT_MS` ทำให้ [[structure/synthetic-fraud-detection/module-case-manager]] ใช้ fallback score แทน ส่งผล false negative rate สูงขึ้น

## การตรวจสอบ

ตรวจ profiling พบว่า feature extraction ที่ต้อง call [[structure/synthetic-fraud-detection/module-velocity-tracker]] และ [[structure/synthetic-fraud-detection/module-device-fingerprinter]] แบบ sequential ใช้เวลารวมมากกว่า inference ของ model เอง — bottleneck ไม่ได้อยู่ที่ ML model แต่อยู่ที่ feature fetching

## สาเหตุ

Feature fetching ถูก implement แบบ sequential await แทนที่จะ parallel await ทั้งสอง service พร้อมกัน ทำให้ latency รวมเป็น A + B แทนที่จะเป็น max(A, B)

## การแก้ไข

แก้ feature fetching ให้ใช้ `Promise.all` เรียก velocity-tracker และ device-fingerprinter พร้อมกัน ลด median latency จาก 95ms เป็น 55ms

## Follow-up

ตรวจสอบ feature fetching pattern ทุกจุดใน ml-scorer และเพิ่ม latency breakdown metric แยก model inference time ออกจาก feature fetch time
