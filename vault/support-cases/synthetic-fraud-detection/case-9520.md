# Case 9520 — Velocity counter reset ทุกชั่วโมงแทนที่จะเป็น sliding window

## สรุปเคส

attack ที่ใช้ volume สูงใน burst หลีกเลี่ยงการตรวจจับได้เป็นเวลา 2 วัน เพราะ velocity counter รีเซ็ตทุกชั่วโมงพอดีแทนที่จะเป็น sliding window ตามที่ออกแบบไว้

## การตรวจสอบ

ตรวจ [[structure/synthetic-fraud-detection/module-velocity-tracker]] พบว่า Redis key ที่ใช้เก็บ counter ถูกตั้ง TTL เป็น 3600 วินาที (1 ชั่วโมง) แบบ fixed แทนที่จะ extend TTL ทุกครั้งที่มี event ใหม่ในลักษณะ sliding window

## สาเหตุ

developer implement `increment` ด้วย `EXPIRE key 3600` ซึ่ง set TTL แบบ absolute เพียงครั้งเดียว แทนที่จะใช้ sorted set with timestamp หรือ algorithm อื่นที่ implement sliding window จริงๆ

## การแก้ไข

ย้าย implementation ไปใช้ Redis sorted set ที่ remove member ที่อายุเกิน window ทุก increment และ replay historical data เพื่อ backfill counter ที่ถูกต้อง

## Follow-up

เพิ่ม integration test ที่ verify sliding window behavior โดย inject event ข้ามจุด boundary ของ window และ document algorithm choice ใน [[convention/synthetic-fraud-detection/signal-schema-convention]]
