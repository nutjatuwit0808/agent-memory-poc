# Case 1319 — Background check vendor ล่มทำวันเริ่มงานเลื่อนทั้ง cohort

## สรุปเคส

vendor ตรวจประวัติภายนอกล่มต่อเนื่อง 3 วัน ทำให้พนักงานใหม่ 12 คนที่ควรเริ่มงานตาม cohort ถัดไปติดอยู่ที่ stage `background_check_pending` ทั้งหมด

## การตรวจสอบ

ตรวจสอบ integration log พบว่า API ของ vendor ตอบ 503 ต่อเนื่องตั้งแต่เช้าวันจันทร์ [[structure/synthetic-hr-onboarding/module-onboarding-workflow-engine]] ไม่มี fallback สำหรับสถานการณ์นี้เลย เพียงแค่รอ webhook ที่จะไม่มีวันมา

## สาเหตุ

ทีมไม่เคยออกแบบ escalation path สำหรับกรณี vendor ล่มระดับนี้ — นโยบาย [[business-logic/synthetic-hr-onboarding/background-check-gating-policy]] มี escalation หลัง 10 วันทำการ แต่ 3 วันแรกยังไม่ถึงเกณฑ์นั้น ทำให้ไม่มีใครรู้ตัวจนพนักงานเริ่มโทรมาถาม HR เอง

## การแก้ไข

ทีม HR ติดต่อ vendor ผ่านช่องทาง account manager โดยตรงแทนการรอ API เพื่อขอผลตรวจแบบ manual สำหรับ cohort นี้ ทำให้เริ่มงานได้ช้ากว่าเดิม 2 วัน

## Follow-up

เพิ่ม alert แยกสำหรับ vendor error rate สูงผิดปกติ (ไม่ต้องรอถึง 10 วัน) และเปิดช่องทางสำรอง manual review กับ vendor ไว้ล่วงหน้าสำหรับสถานการณ์ vendor outage
