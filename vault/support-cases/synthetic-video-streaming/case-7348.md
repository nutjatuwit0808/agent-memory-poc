# Case 7348 — คิว transcode ค้างสะสมช่วง live event ใหญ่

## สรุปเคส

ระหว่าง live event ที่มีผู้ชมพร้อมกันสูงสุดของปี ทีมสังเกตว่า segment ใหม่เข้าคิวเร็วกว่าที่ worker ประมวลผลทันมาก จนผู้ชมเริ่มเจอ buffering ยาวขึ้นเรื่อยๆ

## การตรวจสอบ

เช็ค [[deployment/synthetic-video-streaming/monitoring-alerts]] พบว่าคิว live ของ [[structure/synthetic-video-streaming/module-transcode-worker]] ลึกขึ้นต่อเนื่อง ตรวจ autoscale log พบว่า worker pool ขยายช้ากว่าที่ควรมาก

## สาเหตุ

การจอง live event ล่วงหน้าของ publisher รายนี้ประเมินจำนวนผู้ชมต่ำกว่าความจริงมาก ทำให้ pre-scale ตาม [[business-logic/synthetic-video-streaming/live-event-scaling-policy]] ไม่พอ และ autoscale แบบ reactive ตามปกติ scale ตามการใช้ CPU ซึ่งมี lag อีกหลายนาทีกว่าจะทัน

## การแก้ไข

วิศวกร on-call scale worker pool ด้วยมือทันทีเกินกว่าที่ autoscale คำนวณไว้ พร้อมสลับ ladder ของ event นี้ไปใช้จำนวน rung น้อยลงชั่วคราวตาม edge case ใน [[business-logic/synthetic-video-streaming/transcode-priority-policy]] เพื่อลดภาระต่อ segment

## Follow-up

เสนอให้ publisher ที่จอง live event ต้องกรอกช่วงผู้ชมที่คาดการณ์แบบมี buffer ขั้นต่ำ และพิจารณาตั้ง pre-scale ให้ aggressive กว่าตัวเลขที่ publisher กรอกเสมอ
