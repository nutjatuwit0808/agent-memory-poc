# Case 9160 — ราคาและห้องว่างที่ cache ไว้เก่าเกินไปทำให้ overbook

## สรุปเคส

ลูกค้า 3 รายจองที่พักแห่งเดียวกันในคืนเดียวกันสำเร็จทั้งหมด ทั้งที่ซัพพลายเออร์มีห้องเหลือจริงแค่ 1 ห้อง

## การตรวจสอบ

ตรวจสอบ [[structure/synthetic-travel-booking/module-booking-engine]] พบว่าทั้ง 3 booking ยืนยันสำเร็จในช่วงเวลาห่างกันไม่ถึง 10 นาที ตรง grace period ตาม [[business-logic/synthetic-travel-booking/overbooking-prevention-policy]] พอดี

## สาเหตุ

[[structure/synthetic-travel-booking/module-supplier-sync]] sync ล้มเหลวเงียบๆ ต่อเนื่องเกิน `PRICE_CACHE_STALE_GRACE_SEC` แต่ไม่ได้ mark supplier เป็น degraded เพราะ error ที่เกิดเป็น timeout แบบ intermittent ไม่ใช่ error ที่ระบบตั้งเงื่อนไข mark degraded ไว้ ทำให้ booking-engine ยังคงเชื่อ snapshot เก่าว่าห้องว่างอยู่ 3 ห้อง

## การแก้ไข

ทีม support ติดต่อลูกค้า 2 รายที่จองทีหลังตาม edge case ใน [[business-logic/synthetic-travel-booking/overbooking-prevention-policy]] เสนอที่พักทดแทนระดับเดียวกันในละแวกเดียวกันพร้อมส่วนลดชดเชย ทั้งคู่ตอบรับ

## Follow-up

ขยายเงื่อนไขการ mark degraded ให้ครอบคลุม timeout แบบ intermittent ที่เกินจำนวนครั้งในหน้าต่างเวลาสั้นๆ ไม่ใช่แค่ error แบบชัดเจนอย่างเดียว
