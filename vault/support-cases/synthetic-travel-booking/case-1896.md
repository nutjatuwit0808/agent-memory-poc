# Case 1896 — อีเมลยืนยันแสดงเวลาผิด timezone ทำลูกค้าพลาดเช็คอิน

## สรุปเคส

ลูกค้าเดินทางไปเช็คอินที่พักในต่างประเทศตามเวลาที่ระบุในอีเมลยืนยัน แต่ไปถึงหลังเวลาปิดรับเช็คอินไปแล้วเกือบ 5 ชั่วโมง

## การตรวจสอบ

ตรวจ `renderConfirmationEmail` ใน [[structure/synthetic-travel-booking/module-itinerary-builder]] พบว่าเวลาเช็คอินที่แสดงในอีเมลเป็น timezone ของผู้เดินทาง (ที่ตั้งค่าไว้ในบัญชี) แทนที่จะเป็น timezone ของที่พักตามที่ [[business-logic/synthetic-travel-booking/itinerary-confirmation-timezone-policy]] กำหนด

## สาเหตุ

การแก้ไข template อีเมลรอบล่าสุดสลับตัวแปร timezone สองตัวโดยไม่ตั้งใจ (`travelerTz` กับ `propertyTz`) ผ่าน code review ไปได้เพราะทั้งคู่เป็น string timezone หน้าตาเหมือนกันและ test ที่มีอยู่ทดสอบเฉพาะกรณีที่ทั้งสอง timezone เท่ากันพอดี

## การแก้ไข

แก้ template ให้ใช้ `propertyTz` ที่ถูกต้อง ส่งอีเมลแก้ไขพร้อมโทรแจ้งลูกค้าที่มีการเข้าพักในอีก 48 ชั่วโมงข้างหน้าทุกรายเป็นพิเศษ และช่วยประสานงานกับที่พักของลูกค้าที่พลาดเช็คอินไปแล้ว

## Follow-up

เพิ่ม test case ที่ travelerTz และ propertyTz ต่างกันชัดเจนโดยเฉพาะ ตาม [[convention/synthetic-travel-booking/testing-convention]] เพื่อจับกรณีสลับตัวแปรแบบนี้ได้ในอนาคต
