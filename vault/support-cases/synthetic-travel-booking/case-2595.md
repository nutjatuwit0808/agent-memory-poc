# Case 2595 — Cache invalidate พร้อมกันทำ query ถล่มซัพพลายเออร์

## สรุปเคส

หลัง [[structure/synthetic-travel-booking/module-supplier-sync]] sync รอบใหญ่เสร็จพร้อมกันหลายสิบซัพพลายเออร์ ระบบเจอ error rate พุ่งสูงจากซัพพลายเออร์หลายรายพร้อมกันในเวลาไล่เลี่ยกัน

## การตรวจสอบ

ตรวจ [[structure/synthetic-travel-booking/module-price-cache]] พบว่า event `inventory.sync_completed` จำนวนมากมาถึงพร้อมกันทำให้ cache entry จำนวนมากถูก invalidate ในเวลาเดียวกัน request ค้นหาที่ตามมาเจอ cache miss พร้อมกันหมดจึงยิง query ตรงไปหาซัพพลายเออร์พร้อมกันเป็นจำนวนมาก (thundering herd)

## สาเหตุ

cron schedule ของ sync job หลายซัพพลายเออร์ถูกตั้งเวลาเดียวกันโดยบังเอิญตอนเพิ่มซัพพลายเออร์ใหม่เข้าระบบทีละมาก ไม่มีการกระจาย (jitter) เวลาเริ่ม sync ของแต่ละราย

## การแก้ไข

เพิ่ม random jitter ให้ schedule ของแต่ละซัพพลายเออร์กระจายออกภายในหน้าต่าง 10 นาที แทนที่จะเริ่มพร้อมกันเป๊ะ แก้ปัญหาได้ทันทีในรอบ sync ถัดไป

## Follow-up

ทบทวน [[deployment/synthetic-travel-booking/scaling-policy]] ของ price-cache-service ให้รองรับ burst แบบนี้ได้ดีขึ้นในกรณีที่ jitter ไม่พอในอนาคต
