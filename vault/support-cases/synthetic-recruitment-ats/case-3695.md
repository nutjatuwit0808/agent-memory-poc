# Case 3695 — Bug ตรวจจับ Candidate ซ้ำทำให้เกิด Record แยกกันของคนคนเดียว

## สรุปเคส

recruiter พบว่าผู้สมัครคนหนึ่งสมัครตำแหน่งเดิมซ้ำสองครั้งด้วยอีเมลต่างกันเล็กน้อย (ตัวพิมพ์ใหญ่-เล็กต่างกัน) กลายเป็นสอง candidate record แยกกันโดยสิ้นเชิง ทั้งที่ควรถูกตรวจจับว่าซ้ำ

## การตรวจสอบ

ตรวจ [[structure/synthetic-recruitment-ats/module-candidate-pipeline-tracker]] พบว่า logic เทียบอีเมลเพื่อคำนวณ `DUPLICATE_MATCH_THRESHOLD` เทียบแบบ case-sensitive ทำให้ `Jane.Doe@example.com` กับ `jane.doe@example.com` ถูกมองว่าเป็นคนละคน

## สาเหตุ

การ normalize อีเมลก่อนเทียบไม่ได้ทำ lowercase ให้เรียบร้อยก่อน ทั้งที่มาตรฐานอีเมลถือว่าส่วน domain ไม่ sensitive ต่อตัวพิมพ์เสมอ และในทางปฏิบัติ local part ก็แทบไม่มีใครตั้งใจใช้ตัวพิมพ์ต่างกันเพื่อแยกตัวตน

## การแก้ไข

merge สอง record เข้าด้วยกันด้วยมือผ่าน `mergeDuplicateCandidate` ตาม [[business-logic/synthetic-recruitment-ats/duplicate-candidate-merge-policy]] แล้วแก้ normalize logic ให้ lowercase อีเมลก่อนเทียบเสมอ

## Follow-up

ตรวจสอบ candidate record เก่าทั้งหมดย้อนหลังว่ามี pattern เดียวกันซ่อนอยู่กี่คู่ แล้วรัน merge job แบบ batch สำหรับคู่ที่ตรวจพบ
