# Case 5588 — Threshold ที่ปรับหลวมเกินไปทำให้พลาดความผิดปกติจริงของสต็อกหาย

## สรุปเคส

สินค้าหมวดหนึ่งขายลดลงต่อเนื่อง 3 สัปดาห์เพราะปัญหาสต็อกหายที่ store จริง แต่ [[structure/synthetic-inventory-forecasting/module-anomaly-flagger]] ไม่เคย flag เลยสักครั้ง กว่าจะรู้ตัวก็สูญเสียยอดขายไปมาก

## การตรวจสอบ

ตรวจ [[business-logic/synthetic-inventory-forecasting/anomaly-threshold-policy]] พบว่า category นี้เพิ่งถูกปรับ threshold ให้กว้างขึ้นเมื่อเดือนก่อนหลังมีการร้องเรียนเรื่อง false positive มากเกินไปในช่วงโปรโมชันก่อนหน้า

## สาเหตุ

การปรับ threshold ครั้งนั้นปรับแบบถาวรสำหรับทั้ง category ทั้งที่ต้นเหตุจริงคือปัญหาช่วงโปรโมชันเท่านั้น ทำให้หลังโปรโมชันจบ threshold ที่กว้างเกินไปยังคงใช้งานต่อ และไม่ไวพอจะจับยอดขายลดลงจริงจากปัญหาสต็อก

## การแก้ไข

ปรับ threshold ของ category กลับมาใกล้เคียงค่าเดิม พร้อมเปิดใช้ threshold แบบผ่อนปรนเฉพาะช่วงที่มี `promoFlag = true` จริงตามที่ [[business-logic/synthetic-inventory-forecasting/anomaly-threshold-policy]] ออกแบบไว้ตั้งแต่ต้น

## Follow-up

ห้ามปรับ threshold แบบถาวรเพื่อแก้ปัญหาที่มีสาเหตุเฉพาะช่วงเวลาอีก ต้องใช้กลไก promo-aware threshold ที่มีอยู่แล้วแทนเสมอ เพิ่มเป็นหัวข้อใน [[convention/synthetic-inventory-forecasting/code-review-checklist]]
