# Case 2962 — Schema migration ของ feature store ทำ feature ตัวหนึ่งหายไปเงียบๆ

## สรุปเคส

หลัง migrate schema เพื่อเพิ่ม feature ใหม่ ทีมพบว่าพยากรณ์ของหลาย SKU แย่ลงอย่างค่อยเป็นค่อยไปตลอดสัปดาห์ ไม่มี error ปรากฏที่ไหนเลย

## การตรวจสอบ

เช็คตาม [[deployment/synthetic-inventory-forecasting/feature-store-schema-migration-runbook]] พบว่า field เก่า `priceIndex` ถูกเปลี่ยนชื่อเป็น `price_index_v2` ระหว่าง migration แต่โมเดลเวอร์ชันที่ deploy อยู่ยัง reference ชื่อ field เก่า จึงอ่านค่า default 0 แทนค่าจริงตลอดมาโดยไม่มี error เพราะ field เป็น optional

## สาเหตุ

migration script เปลี่ยนชื่อ field โดยไม่ได้เช็คว่ามี consumer ตัวไหนอ้างชื่อเดิมอยู่บ้าง และ [[structure/synthetic-inventory-forecasting/module-feature-store]] ไม่ reject read ที่ field หายไป แต่คืนค่า default แทน ทำให้ปัญหาไม่ปรากฏเป็น error ที่ใครสังเกตเห็นทันที

## การแก้ไข

เพิ่ม alias field `priceIndex` ชั่วคราวให้ชี้ไปที่ `price_index_v2` เพื่อไม่ให้โมเดลปัจจุบันพัง แล้ววางแผน deploy โมเดลเวอร์ชันใหม่ที่ใช้ชื่อ field ที่ถูกต้องแทน

## Follow-up

เพิ่มขั้นตอนบังคับใน [[deployment/synthetic-inventory-forecasting/feature-store-schema-migration-runbook]] ให้ตรวจสอบ consumer ทั้งหมดของ field ที่จะเปลี่ยนชื่อก่อน migrate เสมอ และทำให้ field สำคัญเป็น required แทน optional
