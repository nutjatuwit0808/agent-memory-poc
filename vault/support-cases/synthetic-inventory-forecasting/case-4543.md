# Case 4543 — Retrain pipeline รั่วข้อมูลอนาคตเข้า training set โดยไม่ตั้งใจ

## สรุปเคส

โมเดลเวอร์ชันใหม่ผ่าน backtest ด้วยตัวเลขดีผิดปกติ แต่พอ deploy จริงกลับแม่นยำน้อยกว่าที่ backtest บ่งชี้มาก ทีมสงสัยว่า backtest มีปัญหา

## การตรวจสอบ

ตรวจ retrain pipeline พบว่า feature `rollingAvg28d` ที่ใช้ฝึกโมเดลบางแถวคำนวณจากช่วงเวลาที่รวมข้อมูลหลัง cutoff date ของ training window ไปด้วย เพราะ job คำนวณ rolling average รันหลัง cutoff แล้วเขียนทับค่าเก่าในตารางเดียวกัน

## สาเหตุ

[[structure/synthetic-inventory-forecasting/module-feature-store]] เก็บ feature แบบ mutable (เขียนทับค่าล่าสุดในที่เดิม) ไม่ได้ versioned ตาม `asOfDate` อย่างเคร่งครัดสำหรับ feature ตัวนี้ ทำให้ training pipeline ที่ query "ค่าล่าสุด" ได้ค่าที่คำนวณจากอนาคตเทียบกับ cutoff date ของตัวเองโดยไม่รู้ตัว

## การแก้ไข

rollback ไม่ deploy โมเดลเวอร์ชันที่มีปัญหา แล้ว retrain ใหม่โดยดึง feature แบบ point-in-time ที่ล็อกค่า ณ วันที่ asOfDate จริงเท่านั้น

## Follow-up

ปรับ [[structure/synthetic-inventory-forecasting/module-feature-store]] ให้ feature ทุกตัวที่ใช้ training ต้อง query แบบ point-in-time เท่านั้น ห้าม query "ค่าล่าสุด" ในบริบทการเทรนโมเดลอีก เพิ่มเป็นข้อบังคับใน [[convention/synthetic-inventory-forecasting/testing-convention]]
