# Case 7539 — Alert Dispatcher ส่ง Page ซ้ำจำนวนมากจาก Retry Bug

## สรุปเคส

on-call วิศวกรได้รับ page เรื่องเดียวกันซ้ำมากกว่า 40 ครั้งภายใน 10 นาทีสำหรับ fault เดียว ทั้งที่ได้ acknowledge ไปตั้งแต่ครั้งแรก

## การตรวจสอบ

ตรวจ [[structure/synthetic-smart-building/module-alert-dispatcher]] พบว่า `suppressDuplicate` เช็คความซ้ำจาก `eventId` แต่ระบบต้นทางสร้าง `eventId` ใหม่ทุกครั้งที่ retry ส่ง event เดิม (แทนที่จะใช้ id เดิมซ้ำ) ทำให้ dedup logic มองว่าทุก retry เป็น event ใหม่เสมอ

## สาเหตุ

module ต้นทางที่ retry การ publish event ไม่ได้ทำ idempotent id generation — สร้าง UUID ใหม่ทุกครั้งที่ retry แทนที่จะ reuse id เดิมของความพยายามครั้งแรก

## การแก้ไข

ปิดการแจ้งเตือนของ fault นี้ด้วยมือชั่วคราวระหว่างแก้ไข แล้วแก้ module ต้นทางให้ reuse `eventId` เดิมเมื่อ retry

## Follow-up

เพิ่ม dedup ชั้นที่สองที่ [[structure/synthetic-smart-building/module-alert-dispatcher]] โดยเช็คจาก `zoneId` + `category` + ช่วงเวลาสั้นๆ ควบคู่กับ `eventId` ไม่พึ่ง idempotent id จากต้นทางอย่างเดียว
