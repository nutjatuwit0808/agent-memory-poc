# Case 5058 — งานซ่อมถูกปิดทั้งที่ Fault เดิมยังไม่หายจริง

## สรุปเคส

พนักงานชั้น 6 ร้องเรียนว่าห้องน้ำเซนเซอร์ไฟยังเสียเหมือนเดิม ทั้งที่ work order ก่อนหน้าถูกปิดไปแล้วว่าซ่อมเสร็จ

## การตรวจสอบ

ตรวจ [[structure/synthetic-smart-building/module-maintenance-scheduler]] พบว่า fault event ประเภทเดียวกันเกิดขึ้นอีกครั้งภายใน 6 ชั่วโมงหลังปิดงาน แต่ `reopenWorkOrder` ไม่เคยถูกเรียก — ระบบสร้าง flow สำหรับ fault ใหม่ปกติแทน

## สาเหตุ

ช่างปิดงานจาก mobile app คนละเวอร์ชันกับที่มี logic เช็ค reopen window 24 ชั่วโมงตาม [[business-logic/synthetic-smart-building/maintenance-work-order-dedup-policy]] — เวอร์ชัน mobile app ที่ยังไม่อัปเดตส่ง event ปิดงานแบบเก่าที่ไม่ trigger การเช็คนี้

## การแก้ไข

reopen work order เดิมด้วยมือ แล้วส่งช่างไปตรวจซ้ำ พบว่าเป็นสายไฟหลวมที่ครั้งแรกแก้ไม่หมด

## Follow-up

บังคับอัปเดต mobile app เวอร์ชันเก่าที่ยังไม่รองรับ reopen logic ให้หมดก่อนสิ้นเดือน และเพิ่ม server-side validation ไม่พึ่งพา client version
