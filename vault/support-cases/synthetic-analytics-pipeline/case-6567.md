# Case 6567 — ต้นทางเปลี่ยน Schema เงียบๆ ทำ Dashboard พังไม่มีใครรู้

## สรุปเคส

ทีมการตลาดแจ้งว่าตัวเลขในแดชบอร์ดยอดขายรายวันแสดงค่า 0 มาสามวันติดต่อกัน ทั้งที่ยอดขายจริงไม่ได้ผิดปกติ

## การตรวจสอบ

ตรวจ [[structure/synthetic-analytics-pipeline/module-schema-registry]] พบว่าระบบต้นทาง (CRM ภายนอก) เปลี่ยนชื่อ field `total_amount` เป็น `amount_total` โดยไม่แจ้งล่วงหน้า และ [[structure/synthetic-analytics-pipeline/module-transform-engine]] แปลงข้อมูลโดยเติมค่า default 0 ให้ field ที่หายไปแทนที่จะ error

## สาเหตุ

กฎการแปลงของ dataset นี้ตั้งค่า `NULL_FILL_STRATEGY_DEFAULT` เป็น fallback ที่ผ่อนปรนเกินไปสำหรับ field สำคัญ ทำให้เมื่อ field หายไปจริง ระบบเติม 0 แทนที่จะปฏิเสธข้อมูลตาม [[business-logic/synthetic-analytics-pipeline/quality-gate-policy]] — schema change ที่ควรถูกจับว่าเป็น breaking change กลับหลุดผ่านไปได้เพราะ column ใหม่ไม่ได้ถูก mark เป็น required

## การแก้ไข

เพิ่ม field `total_amount` เดิมกลับเข้า mapping โดยชี้ไปที่ `amount_total` ใหม่ แล้ว backfill ข้อมูล 3 วันที่ผิดพลาดด้วยการรัน transform ใหม่จาก raw extract ที่ยังเก็บไว้อยู่

## Follow-up

เปลี่ยนกฎให้ field ที่เคย mark เป็น critical สำหรับ dashboard ต้อง reject (ไม่ใช่ fill default) เมื่อหายไปจากต้นทาง และเพิ่ม alert แยกเมื่อ column ที่คาดว่าต้องมีหายไปจาก extract
