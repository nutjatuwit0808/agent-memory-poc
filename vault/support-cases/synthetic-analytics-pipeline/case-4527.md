# Case 4527 — Backfill ขนาดใหญ่แย่ง Capacity จน Incremental Load ค้าง

## สรุปเคส

ทีมหลายทีมรายงานพร้อมกันว่า dashboard ที่ควรอัปเดตทุกชั่วโมงหยุดอัปเดตไปนานเกือบ 4 ชั่วโมงในบ่ายวันหนึ่ง

## การตรวจสอบ

ตรวจ [[structure/synthetic-analytics-pipeline/module-warehouse-loader]] พบว่า backfill job ขนาดใหญ่ (re-process ข้อมูล 6 เดือนหลังแก้ transform bug) กำลังใช้ stream เกือบทั้งหมดใน connection pool ของ warehouse ทำให้ incremental load งานปกติต้องรอคิวยาว

## สาเหตุ

backfill job นี้ถูก trigger แบบ manual โดยไม่ได้ผ่านการตรวจสอบ priority ตาม [[business-logic/synthetic-analytics-pipeline/backfill-load-policy]] อย่างครบถ้วน — คนที่ trigger ไม่รู้ว่า default behavior ของ backfill ควรถูก pause อัตโนมัติเมื่อ incremental load รอคิว เพราะ flag การตั้งค่านั้นถูกปิดไว้ผิดพลาดตอน config ล่าสุด

## การแก้ไข

pause backfill job ด้วยมือทันทีเพื่อคืน capacity ให้ incremental load ไล่ตามให้ทัน แล้วค่อยรัน backfill ต่อในช่วงดึกที่โหลดของระบบต่ำแทน

## Follow-up

แก้ default config ของ pause-on-contention ให้เปิดเสมอสำหรับ backfill job ทุกตัว เว้นแต่จะขอ priority override ตาม [[business-logic/synthetic-analytics-pipeline/backfill-load-policy]] อย่างชัดเจนเท่านั้น
