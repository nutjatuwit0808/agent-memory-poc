# Case 1457 — Instructor ถูก Book สอนสองที่พร้อมกัน

## สรุปเคส

Instructor รายหนึ่งถูก schedule สอน live session สองงานพร้อมกันในวันเดียวกัน เวลาเดียวกัน ทำให้ต้องยกเลิก session หนึ่งในเวลาเที่ยงคืนก่อนวันสอน

## การตรวจสอบ

ตรวจสอบ [[structure/synthetic-e-learning/module-instructor-scheduler]] พบว่า scheduling admin สอง team ต่างทำ assignment พร้อมกันโดยไม่รู้ว่าอีกทีมกำลังทำอยู่ conflict check ทำงานถูกต้อง แต่ทั้งสอง assignment ผ่าน check ก่อนที่อันแรกจะ commit

## สาเหตุ

Conflict check และ session creation ไม่ใช่ atomic operation — ทั้งสอง transaction อ่านตาราง schedule แล้วไม่พบ conflict ก่อนที่อันไหนจะ write สำเร็จ ทำให้ทั้งคู่ผ่านพร้อมกัน

## การแก้ไข

เพิ่ม pessimistic lock บนช่วงเวลาของ instructor ขณะ create session เพื่อป้องกัน concurrent booking และ reschedule session ที่ถูกยกเลิกให้ผู้เรียนใหม่

## Follow-up

ตรวจสอบว่าการ lock strategy นี้ไม่ทำให้ performance ของ scheduling ช้าลงมากเกินไป เพราะ instructor schedule เป็น operation ที่ทำบ่อย ดู [[deployment/synthetic-e-learning/scaling-policy]]
