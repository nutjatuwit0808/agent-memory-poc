# Workshop 04 — Hybrid router

## คำถามตั้งต้น

- ทำไม production ไม่เลือก backend ตัวเดียว
- layer pre-filter ช่วยตรงไหน วัดเป็นตัวเลขได้เท่าไหร่
- routing ที่ deterministic ทำได้แค่ไหนโดยไม่ต้องใช้ LLM

## ทฤษฎีสั้น (เขียนลง README ตอนทำ)

จาก WS01–03 จะเห็นว่าไม่มี backend ไหนชนะทุก query kind — router คือการยอมรับข้อเท็จจริงนั้นแล้วเลือกเครื่องมือตามงาน
สองกลยุทธ์: **route** (เลือกตัวเดียวจากรูปร่าง query) กับ **fuse** (ยิงทุกตัวแล้วรวมผล) — คนละ trade-off คนละราคา

## W4-1 — Query classifier (deterministic)

**ไฟล์:** `src/search/router.ts`

**ทำ:** กฎที่คำนวณได้ ห้ามเรียก LLM (CLAUDE.md §2.1) — ทุก query ต้องอธิบายได้ว่าทำไมไปทางนั้น

กฎตั้งต้นที่แนะนำ (ปรับตามผลจริงจาก WS01–03):

| สัญญาณใน query | ไป backend | เหตุผลจากตัวเลข workshop ก่อน |
|---|---|---|
| ครอบ `"..."` / มี `_` `-` `.` / ตัวพิมพ์ใหญ่ล้วน / ดูเป็น identifier | ripgrep | exact match ชนะขาดใน W1 |
| 1–3 คำ ทั่วไป | fts5 | BM25 เก่งเรื่อง keyword สั้น |
| ≥4 คำ / เป็นประโยคคำถาม | vector | semantic ชนะใน W3 |
| ระบุ layer/tag มา | pre-filter ก่อนแล้วค่อยส่งต่อ | ลด candidate set ก่อนงานหนัก |

**ต้อง log เหตุผล:** ทุกผลลัพธ์ต้องบอกได้ว่าเข้ากฎข้อไหน — router ที่อธิบายไม่ได้คือ black box ซึ่งขัดกับเป้าหมายทั้งโปรเจกต์

- [ ] ไม่มี LLM call
- [ ] output มี `routedBy: <rule-id>` ทุกครั้ง
- [ ] มี unit test ครอบทุกกฎ
- [ ] กฎทุกข้ออ้างอิงตัวเลขจาก WS01–03 ได้ว่าทำไมตั้งแบบนี้

## W4-2 — Layer pre-filter

**ทำ:** ถ้า query ระบุ layer → ตัด candidate ก่อนเข้า backend แล้ววัดว่าประหยัดไปเท่าไหร่ในแต่ละ backend

ผลจะไม่เท่ากันและนั่นคือประเด็น:
- ripgrep — ลดจำนวนไฟล์ที่ต้องอ่านจริง (ประหยัดมาก ต่างจาก post-filter ใน W1-4)
- fts5 — SQLite ก็ทำได้อยู่แล้ว (ประหยัดน้อย)
- vector — ลดจำนวน dot product แต่ยังต้อง embed query อยู่ดี (ประหยัดปานกลาง)

**DoD**
- [ ] ตาราง latency มี/ไม่มี pre-filter × 3 backend
- [ ] อธิบายได้ว่าทำไมแต่ละตัวประหยัดไม่เท่ากัน
- [ ] pre-filter ไม่ทำให้ recall ตกในเคสที่ layer ถูกต้อง

## W4-3 — Fusion (RRF)

**ทำ:** Reciprocal Rank Fusion — `score = Σ 1/(k + rank_i)`, k=60

เลือก RRF เพราะ **รวมอันดับไม่ใช่รวมคะแนน** — score ของ BM25 (ติดลบ, ไม่มีขอบเขต) กับ cosine (0–1) เอามาบวกกันตรงๆ ไม่ได้ และ RRF คำนวณตามด้วยมือได้ ตรงกับ CLAUDE.md §2.1

**ต้องมี:** ตารางแสดงการคำนวณ RRF ของ 1 query จริง ทีละขั้น — เห็น rank จากแต่ละ backend แล้วเห็นผลรวม

**DoD**
- [ ] สูตร RRF เขียนเอง มี comment
- [ ] มีตัวอย่างคำนวณทีละขั้นใน README
- [ ] วัด latency: fusion ต้องยิงทุก backend → แพงกว่า route แน่นอน ต้องมีตัวเลขว่าแพงกว่ากี่เท่า
- [ ] เทียบ recall: route vs fusion vs backend เดี่ยวที่ดีที่สุด
