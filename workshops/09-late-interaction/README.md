# Workshop 09 — Late interaction / multi-vector (ColBERT)

## สถานะ: หยุดที่ W9-1 (spike) — ตัดสินใจไม่ทำต่อ

ต่างจาก Workshop 08 (หา multilingual SPLADE ไม่เจอเลย) — workshop นี้**หาโมเดลเจอจริง** แต่ตัดสินใจไม่ดาวน์โหลดมาลองเพราะขนาดไฟล์และความไม่แน่นอนของผลลัพธ์ไม่คุ้มกับต้นทุน บันทึกไว้เป็นผลการค้นคว้าที่มีค่า ไม่ใช่ผลว่างเปล่า

## คำถามตั้งต้น (ตอบไม่ได้ในรอบนี้)

- เก็บ embedding ทุก token แทนที่จะยุบเหลือเวกเตอร์เดียว แม่นขึ้นจริงไหมบน vault นี้
- index ใหญ่ขึ้นกี่เท่า และยังคุ้มไหม
- MaxSim ต่างจาก cosine ของเวกเตอร์เดียว (WS03) ตรงไหน

## ทฤษฎีสั้น (ยังใช้ได้ แม้ไม่ได้ implement)

WS03 ทำ **mean pooling** — ยุบ embedding ของทุก token ในเอกสารให้เหลือเวกเตอร์เดียว 384 มิติ ข้อมูลระดับคำหายไปหมด **Late interaction (ColBERT)** เก็บเวกเตอร์ของทุก token ไว้ แล้วคำนวณ MaxSim ตอน query:

```
score(doc) = Σ (token i ใน query) max (token j ใน doc) [q_i · d_j]
```

แต่ละ token ใน query ไปหา token ที่ตรงที่สุดของตัวเองใน document แล้วรวมคะแนน — จับคู่ระดับคำได้เหมือน BM25 แต่ยัง semantic เหมือน dense ตำแหน่งบนสเปกตรัม: bi-encoder (เร็วสุด) → **late interaction** → cross-encoder (WS07, แม่นสุด/ช้าสุด)

## W9-1 — สิ่งที่ค้นพบจริง

### หาโมเดลได้: `jinaai/jina-colbert-v2`

| | ค่า |
|---|---|
| Multilingual | ✅ ยืนยันจริง — มี tag ภาษาแยกกว่า 89 ภาษา รวม `th` (ไทย) ชัดเจนในรายการ tag |
| Architecture | `HF_ColBERT` (custom, ฐาน XLM-RoBERTa-large) |
| hidden_size | 1024 (24 layers, 16 heads) — ใหญ่กว่า MiniLM ของ WS03 (384-dim, 12 layers) มาก |
| ColBERT output dim | 128 (ตาม README ต้นฉบับ, มีตัวเลือก 96/64 ด้วย matryoshka) |
| ONNX ในตัว repo | ✅ มี `onnx/model.onnx` (3.8MB, แค่ graph) + `onnx/model.onnx_data` (**น้ำหนักจริง**) |
| **ขนาดจริง (resolve ผ่าน LFS/Xet แล้ว)** | **model.onnx_data = 2,233,790,464 bytes ≈ 2.08 GB** |

### เหตุผลที่ตัดสินใจไม่ดาวน์โหลดมาลอง

**1. ขนาดใหญ่กว่าทุกโมเดลที่โปรเจกต์เคยใช้ประมาณ 16 เท่า** — MiniLM (WS03) 465MB, bge-reranker (WS07) 283MB, ตัวนี้ 2.1GB ต้นทุนดาวน์โหลด+พื้นที่ดิสก์ไม่สมเหตุสมผลสำหรับ workshop ขนาด 55 note ที่ทุก workshop ก่อนหน้าใช้เวลาไม่กี่วินาทีถึงไม่กี่นาที

**2. ความไม่แน่นอนของผลลัพธ์ ก่อนดาวน์โหลดด้วยซ้ำ** — `config.json` ระบุ `architectures: ["HF_ColBERT"]` ซึ่งเป็น class เฉพาะ แต่ `auto_map` ที่ประกาศไว้ชี้ `AutoModel` ไปที่ `XLMRobertaModel` **ธรรมดา** ไม่ใช่ `HF_ColBERT` — แปลว่าการโหลดผ่าน `AutoModel` มาตรฐานมีความเสี่ยงจะได้แค่ raw hidden state ของ XLM-RoBERTa-large (1024 มิติ) ไม่ใช่ embedding ที่ผ่าน ColBERT projection head จริง (ที่ควรลดเหลือ 128 มิติตามที่ README ต้นฉบับพูดถึง) **นี่คือปัญหาเดียวกับที่เจอใน Workshop 08** (BGE-M3's `sparse_linear.pt` แยกออกจาก ONNX export) — โมเดลมี ONNX แต่ไม่มีหลักฐานชัดเจนว่า ONNX นั้น export "หัวเฉพาะทาง" (specialized head) ที่ทำให้โมเดลกลายเป็น ColBERT จริงๆ ออกมาด้วย ถ้าใช้แล้วได้แค่ raw encoder output จะเป็นการทำ MaxSim บนเวกเตอร์ที่**ไม่เคยถูกฝึกมาให้เปรียบเทียบกันข้ามประโยคแบบ ColBERT** ตรงตามความเสี่ยงที่ D-แผนเตือนไว้ตั้งแต่ต้น ("เอา BERT ธรรมดามาทำ MaxSim จะได้ผลที่ตีความไม่ได้")

**3. ไม่มีทางตรวจสอบข้อ 2 ได้โดยไม่ดาวน์โหลดเต็มก่อน** — onnxruntime ต้องมีน้ำหนักครบถึงจะรัน inference ทดสอบได้แม้แต่ครั้งเดียว ทำให้ไม่มี "ทางลัด" ตรวจสอบความถูกต้องก่อนจ่ายต้นทุนเต็ม

**สรุป: พบ candidate ที่ตรงเงื่อนไข multilingual+ONNX จริง (ต่างจาก WS08 ที่หาไม่เจอเลย) แต่ต้นทุน (2.1GB) กับความเสี่ยงเรื่องความถูกต้อง (custom architecture ไม่ผ่าน auto_map มาตรฐาน) รวมกันแล้วไม่คุ้มที่จะลงทุนดาวน์โหลดสำหรับ case study ขนาดนี้**

## ผลที่ตามมา — W9-2 ถึง W9-5 ไม่ได้ทำ

ไม่มี `colbert.backend.ts`, ไม่มี multi-vector embedding cache, ไม่มีตัวเลขเปรียบเทียบ dense vs late-interaction ให้รายงาน — บันทึกไว้ตรงๆ แทนการเดาหรือประมาณตัวเลข

## สิ่งที่ยังใช้ได้จากงานวิจัยนี้

ถ้าจะกลับมาทำ workshop นี้ต่อในอนาคต จุดที่ต้องทำก่อนเป็นอันดับแรกคือ**ตรวจสอบ dimension ของ ONNX output จริง** (ผ่าน `onnx.helper`/netron หรือเครื่องมือตรวจ graph metadata โดยไม่ต้องรัน inference เต็ม) ว่าเอาต์พุตสุดท้ายคือ 128 มิติ (ColBERT space จริง) หรือ 1024 มิติ (raw encoder) — ถ้าตรวจสอบล่วงหน้าแบบนี้ได้ก่อนดาวน์โหลดเต็ม จะลดความเสี่ยงของการเสียเวลา/พื้นที่ดิสก์ไปกับโมเดลที่ใช้ไม่ได้จริงตามจุดประสงค์

โมเดลขนาดเล็กกว่าที่อาจคุ้มค่าตรวจสอบต่อ (ยังไม่ได้ตรวจ): `answerdotai/answerai-colbert-small-v1` (ภาษาอังกฤษ, เล็กกว่ามาก) — แต่ไม่ผ่านเงื่อนไข multilingual ตั้งแต่ต้น จึงไม่ใช่ตัวเลือกที่เหมาะกับ vault นี้เช่นกัน
